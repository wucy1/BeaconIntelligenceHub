# 離線行為與地圖限制

## 目前已支援（C1）

| 能力 | 說明 |
|------|------|
| 危機快照 | 至少連線開啟一次 → `active-window` 寫入 IndexedDB |
| 離線新增回報 | 相片 + payload 入佇列，上線後 `syncQueue` |
| 地圖視野鎖定 | 離線時鎖定 **bounds + zoom**，避免平移／縮放載入未快取 OSM 瓦片而整片灰屏 |

## 地圖為何會變灰？

底圖使用 **OpenStreetMap 線上瓦片**（`tile.openstreetmap.org`）。離線時：

1. 瀏覽器**僅可能**顯示先前連線時快取過的瓦片。
2. 平移或縮放會請求**新**瓦片 → 網路失敗 → Leaflet 顯示灰底。
3. 這**不是** bug，而是未實作「離線瓦片包」時的預期行為。

## C1.5 緩解（已實作）

`OfflineMapViewLock`：進入離線填報模式後，在 `moveend` 將地圖 **maxBounds** 與 **minZoom = maxZoom** 固定在目前視野。使用者仍可：

- 拖動回報圖釘
- 在已快取畫面內小幅平移（若瓦片仍在快取內）

不建議在離線時依賴縮放或大幅平移。

**建議流程（現場）**

1. **有網路時**開啟 App，允許定位，讓地圖飛到現場並載入一圈瓦片。
2. 在要填報的縮放層級（約 z16）稍等瓦片載完。
3. 再開飛航模式 → 視野會鎖在該處，灰屏機率大幅降低。

## 未來選項（C4 — 選做）

| 方案 | 優點 | 缺點 |
|------|------|------|
| **A. 連線時「預下載此區域」** | 離線可有限度平移 | 需 IndexedDB 存瓦片；須遵守 OSM [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)（禁止大量預抓取）；實作量中等 |
| **B. 鎖定視野（現狀）** | 實作快、無額外儲存 | 無法離線探索新區域 |
| **C. 降級底圖** | 無瓦片依賴 | 僅色塊／簡圖，辨識度差 |
| **D. 自建／授權瓦片 + SW** | 可合規快取 | 需基礎設施與預算 |

「快速下載完整地圖」在實務上通常指 **某一 AOI + 縮放級距**（例如半徑 2 km、z14–17），而非整縣市；全島預抓既不現實也可能違反 OSM 政策。

## 與產品模型的關係

`unspecified` 階段無官方 bounds；離線鎖定的是**裝置上已載入的視野**，不是管理員 AOI。管理員日後劃定範圍只影響**顯示篩選**，不影響離線能否提交。
